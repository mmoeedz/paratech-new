Technical, UX & Conversion Audit

Paratech Website
Audit Report

A production-readiness review of the Next.js marketing site, focused on reliability, accessibility, performance, SEO, and lead conversion.

Prepared for Paratech22 August 2026

Executive summary

Verdict: The site has a polished visual foundation and clear positioning, but it is not ready for a public production launch. A release-blocking build failure prevents deployment, and the lead-capture flow is not dependable enough for a commercial agency website.

The design system is cohesive: the dark/copper palette, typography, navigation, responsive layouts, service hierarchy, generated metadata, and reduced-motion consideration are all good starting points. The priority now is to make the site trustworthy in operation: it must build, receive enquiries reliably, present consistent company details, and be tested as a real customer would use it.

Audit basis: source-code review, TypeScript check, ESLint check, and attempted Next.js production build. ESLint passed; TypeScript and production build failed.

Priority findings

Critical · release blocker

Production build and type-check fail

AutomationShowcase.tsx imports WORKFLOWS, but src/data/workflows.ts only exports AUTOMATION_STEPS. The services page therefore fails at build time. The TypeScript check also reports implicit any values resulting from that missing import.

Impact: the current project cannot produce a deployable production build; the services page is unavailable in a release.

Recommendation: decide whether the automation showcase should render workflow examples or automation steps, then align the component and data module. Add a required typecheck script and make it part of continuous integration alongside lint and build.

High · conversion

The contact form does not submit enquiries to a server

The form prevents the browser’s normal submit behavior and constructs a mailto: link. It marks the enquiry as sent immediately after attempting to open the visitor’s email program.

Impact: visitors without a configured mail client can lose their enquiry. There is no delivery confirmation, CRM handoff, analytics event, spam defence, server validation, or reliable mobile behavior.

Recommendation: implement a server-side action or a secure API route backed by an email/CRM provider. Validate fields on the server, add a honeypot plus rate limiting, show genuine success/error feedback, and send both team notification and customer acknowledgement.

High · trust

Contact information is inconsistent and one footer link is invalid

The site uses both hello@paratech.agency and contact@paratechsolutions.com. In the footer, the latter is used as an href without the mailto: protocol.

Impact: the footer contact link does not open an email client, and inconsistent domains reduce credibility and complicate lead routing.

Recommendation: choose one public identity and one inbox, store it once in the site configuration, and render that value everywhere. Correct the footer to use a valid mailto: link.

High · accessibility

The mobile navigation labels itself modal but does not fully trap focus

The menu correctly handles Escape, initial focus, background inertness, and scroll locking. However, it uses aria-modal="true" without a full Tab/Shift+Tab focus loop.

Impact: keyboard users can potentially move focus outside what is announced as a modal dialog, creating a confusing navigation experience.

Recommendation: use a tested dialog primitive or implement a focus trap and focus restoration. Test with keyboard-only navigation and a screen reader.

Content and conversion review

Positioning is clear; proof is thin

The core proposition—one partner for websites, software, growth, and automation—is easy to understand. The pages describe services clearly, but a prospect still needs more evidence before making contact. This is especially important for an agency selling higher-trust work such as automation and custom software.

  • Add real case studies with client context, constraints, approach, delivery period, and measurable results.
  • Add testimonials, client logos, partner badges, or concise proof points where legally permitted.
  • Clarify ideal customer profile, geographic scope, typical engagement size, and discovery process.
  • Replace some repeated “Start a project” calls to action with intent-specific options such as “Get an automation assessment” or “Book a discovery call.”

Insights should become a genuine content system

The Insights page currently contains thoughtful hard-coded notes. It will be stronger for credibility and organic search when each entry becomes a dedicated article with its own URL, title, publication date, author, related content, metadata, and Article schema.

Visual and content polish

The visual language is consistent and professional. Before launch, ensure the oversized footer logo is intentional, remove unused image assets if they are not part of the future content plan, and check every section on small screens at 200% zoom.

What is already working well

  • Strong, consistent visual identity with a clear hierarchy and readable contrast direction.
  • Good component reuse across navigation, calls to action, service cards, sections, and metadata.
  • App Router conventions are mostly used well: page metadata, robots, sitemap, icons, Open Graph image, and custom 404 exist.
  • Accessibility basics are better than average: skip link, visible focus treatment, labelled form controls, reduced-motion styles, and semantic landmarks are present.
  • The services information architecture is logical and individual service routes are generated statically.
